# KFAFH-IS-Validation-System-Frontend
 Laboratory Equipment Validation System

## Overview

This project is a web-based system developed to support the validation and verification of laboratory equipment data within a medical laboratory department.

The project was developed during my training period, where I was responsible for the **Front-End Development** of the system.

The original system had a basic and unorganized interface. My role was to improve and modernize the user interface, organize the workflow, and create a clearer and more user-friendly experience for users working with laboratory equipment data.

## My Role

**Front-End Developer**

My main responsibilities included:

* Analyzing the existing system and identifying areas for UI improvement.
* Meeting with the laboratory supervisor to understand the existing workflow and requirements.
* Designing and developing the front-end interfaces.
* Improving the structure and usability of the existing system.
* Developing forms for entering and validating laboratory equipment data.
* Developing dashboard and request-management interfaces.
* Creating authentication and user-management interfaces.
* Implementing responsive layouts for different screen sizes.
* Attending regular meetings with my training supervisor to review progress and discuss updates.
* Implementing changes and improvements based on continuous feedback.

## Main Features

The system includes several interfaces to support the laboratory equipment validation workflow:

* User Login
* User Registration
* Forgot Password
* Reset Password
* Home Page
* Validation Requests
* Create Validation
* Equipment Data Forms
* Dashboard
* Request Status Monitoring
* Validation Workflow
* Responsive User Interface

## Development Process

The project was developed through an iterative process based on requirements gathering and continuous feedback.

### 1. Understanding the Existing System

I first reviewed the existing system to understand its workflow, structure, and interface limitations.

### 2. Requirements Gathering

I met with the laboratory supervisor to understand the department's workflow and the information required for validating laboratory equipment data.

### 3. Front-End Development

I designed and developed the required interfaces based on the gathered requirements.

### 4. Continuous Review

I regularly met with my training supervisor to demonstrate the progress, discuss updates, and receive feedback.

### 5. Improvements

The interfaces were continuously updated and improved based on the feedback and requirements discussed during the meetings.

## Objective

The main objective of this project was to improve the existing laboratory equipment validation interface by creating a more organized, intuitive, and user-friendly front-end experience.

The improved interface helps organize the validation workflow and makes it easier for users to enter, review, and monitor laboratory equipment data.
