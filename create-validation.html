💡 Test Method Legend

Testing method definitions

Normal Testing: Testing the functional and structural integrity of the system. Demonstrating that the system performs as intended under normal conditions. Input within-range data.

Invalid Case Testing: Use invalid inputs to demonstrate system checks for input errors.

Special Case Testing: Using input values that are most likely to cause program errors or test how the system responds to unsuitable data. Using input values of specific types of data or no data entry in a field will help to test the system defaults.

Parallel Testing: Testing the systems as a whole by running two systems in parallel and comparing the outputs. Parallel testing is the most common type of testing, but it cannot be relied upon as the sole criterion for validating the system because it focuses on a narrow range of values during normal test runs.

Boundary Testing: Where there is a range of valid input, values should be tested which are within the range of valid entries, at the limits of the range of valid entries, and beyond the range of valid entries.

Stress Testing: Where a system has a requirement to perform at a certain level, test cases should be developed to challenge the system at and beyond those levels.

Input Testing: Testing of data input function should include valid values, invalid values, null and zero values of an incorrect data type.

RTM: Reference test number identity — the sample number generated from the new system when using parallel testing.
